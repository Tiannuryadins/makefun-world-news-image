## 7. Compliance verification — Saturday 14 Nov 2026, ~18:10–18:25 WIB (verifier)

Requirements were re-verified per bounty from the public make.fun API
(`GET https://make.fun/api/competitions` and
`GET /api/competitions/news-image-01/requirements`):

- Output: one image to `/output/entry.png` (harness `program/v1`).
- Gate: a whole PNG or JPEG, **at most 1 MiB and 1024 by 1024 pixels**.
- Runtime: `python3 -P -s /bot/main.py` (Python 3.13, **stdlib only** —
  the official `python` image has no Pillow) in a sandbox with no
  network, repo mounted read-only at `/bot`, empty `/output` dir,
  60 s wall budget, 1 CPU, 512 MiB RAM, 64 pids.
- Determinism: two runs must write the same bytes.

**Findings — the entry as built was NOT compliant, in three ways:**

1. **Fatal: `main.py` required Pillow at run time** (`from PIL import ...`
   at module top). The grader has no Pillow, so the entry would crash
   immediately with `ModuleNotFoundError: No module named 'PIL'` and fail
   `run_completes`. Reproduced locally in a stdlib-only venv.
2. **Poster was 1600×2300 px**, exceeding the 1024×1024 gate (file size
   343,715 bytes was under 1 MiB, but dimensions failed).
3. **Output path was wrong**: the program wrote
   `world_news_13_nov_2026.png` next to `main.py` — the grader reads
   `/output/entry.png`, and the repo is mounted read-only, so the write
   would have failed even with Pillow present.

**Fixes applied by the verifier:**

1. The Pillow drawing code was moved unchanged in structure to
   `render_poster.py` (build-time renderer, not run by the grader), and
   the layout was redesigned for a **square 1024×1024** canvas: masthead,
   lead story (unchanged deck), stats strip, 3×3 story grid, sources
   footer. All 10 stories are kept; the 9 card bodies were trimmed to
   one-to-two-line summaries (each verified to wrap to ≤2 lines at the
   real font sizes — the renderer asserts this, plus headline ≤2 lines
   and no card/footer overflow, so layout regressions fail loudly).
   Re-rendered poster: **1024×1024 PNG, 129,203 bytes**, visually
   inspected — all text legible, nothing clipped.
2. `main.py` was rewritten as a **stdlib-only** program that embeds the
   rendered PNG as base64 and writes it to `/output/entry.png`
   (`MAKEFUN_OUTPUT_DIR` override for local testing, `./output/`
   fallback, argv path override) — the same pattern as the verified
   `ai-happy-01` entry. It self-checks the gate on every run with a
   stdlib PNG (IHDR) parser.
3. `world_news_13_nov_2026.png` in this folder is now the new 1024×1024
   poster (byte-identical to what `main.py` writes).

To change the poster after a re-render: run `render_poster.py` (it
overwrites `world_news_13_nov_2026.png`, which `main.py` reads at run
time) and update the size/hash in the docstring and §7 test record
below. (Before the 14 Nov ~18:30 fix, `main.py` embedded the PNG as
base64; see the fix note at the end of this file.)
